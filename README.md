# RustyZoo

RustyZoo is an open-source reimplementation of the Zoo Tycoon (2001) game engine, in the spirit of [OpenRCT2](https://openrct2.io/): a standalone program, written in Rust, that loads the data of your own copy of the game. It targets Windows 11 (x64), macOS (arm64 and x86_64, as a universal binary) and Linux (x86_64).

## Status

Pre-alpha. Nothing is playable yet: the repository currently contains a small core library and a command that opens a window and an audio device to prove that the toolchain and CI work.

## You need the original game

RustyZoo only loads the data of an existing installation, so you need your own copy of Zoo Tycoon: the full game (Complete Collection) or one of the free trials below. This project contains no original code or assets. It is not affiliated with or endorsed by Microsoft or Blue Fang Games.

### The free official trials

Microsoft still hosts two free trials, which you may install and use: [Zoo Tycoon](https://download.microsoft.com/download/zootycoon/Trial/2.0/W9X2KMeXP/EN-US/ZooTycoon.exe) and [Marine Mania](https://download.microsoft.com/download/zootycoon/Trial/1.0b/WIN98XP/EN-US/mardinotrial.exe). RustyZoo never redistributes them. To try RustyZoo without buying the game, run `ci/fetch-trials.sh <dir>`: it downloads both installers from Microsoft, checks their checksums and extracts them, without running anything, with [7-Zip](https://www.7-zip.org/) (`7z` or `7zz` must be on the PATH). It leaves two game folders, `<dir>/base-trial` and `<dir>/expansion-trial`, to pass to `--data`. CI does the same to run the commands on real data (`ci/check-trials.sh` lists them).

## Building

You need CMake and a C compiler (SDL3 is built from source and linked statically, so no system SDL is required) and the Rust toolchain pinned in `rust-toolchain.toml` (installed automatically by [rustup](https://rustup.rs/)).

```
cargo build --release
cargo run --release -- window-smoke
```

On Windows use the Visual Studio build tools (MSVC); on macOS the Xcode command line tools.

On Linux, SDL only builds the real window and sound backends (X11, Wayland, ALSA, PulseAudio, PipeWire, ...) if their development packages are installed. Without them the build still succeeds, but the binary can only use the headless `offscreen` and `dummy` drivers. On Ubuntu 22.04 or newer:

```
sudo apt-get install libasound2-dev libpulse-dev libaudio-dev libfribidi-dev \
  libjack-dev libsndio-dev libx11-dev libxext-dev libxrandr-dev libxcursor-dev \
  libxfixes-dev libxi-dev libxss-dev libxtst-dev libxkbcommon-dev libdrm-dev \
  libgbm-dev libgl1-mesa-dev libgles2-mesa-dev libegl1-mesa-dev libdbus-1-dev \
  libibus-1.0-dev libudev-dev libthai-dev libusb-1.0-0-dev libpipewire-0.3-dev \
  libwayland-dev libdecor-0-dev liburing-dev
```

Other distributions: see [SDL's Linux build dependencies](https://github.com/libsdl-org/SDL/blob/main/docs/README-linux.md).

## Usage

Point RustyZoo at the install folder of your game (the one that holds `zoo.ini`) with `--data`, or with the `ZT_DATA_DIR` environment variable:

```
rustyzoo --data "/path/to/Zoo Tycoon" ls 'animals/lion*'   # list files, sorted; * matches any text
ZT_DATA_DIR="/path/to/Zoo Tycoon" rustyzoo cat animals/lion.ai > lion.ai   # write one file to stdout
rustyzoo --data "/path/to/Zoo Tycoon" dump-strings lang0.dll   # string table of a resource DLL, as ID<TAB>text lines
rustyzoo --data "/path/to/Zoo Tycoon" dump-strings lang0.dll --text LION_GENERAL   # one long text, as stored (Windows-1252)
rustyzoo --data "/path/to/Zoo Tycoon" strings   # the texts as the game resolves them, with the library that supplies each
rustyzoo --data "/path/to/Zoo Tycoon" check-config   # read all configuration files (.ai, .cfg, .lyt, ...), report what is empty or ignored
rustyzoo --data "/path/to/Zoo Tycoon" types   # the entity types (class, type, subtype, name id, footprint, base animation), then counts per class
rustyzoo --data "/path/to/Zoo Tycoon" check-behaviours   # calls per operation name of the behaviour sets of every definition file, and the ambient tables; exit 1 on an unknown operation
rustyzoo --data "/path/to/Zoo Tycoon" check-behaviours --type lion   # the ambient rows and the calls of one type, as parsed
rustyzoo dump-sprite animals/lion/f/walk/E out/   # one PNG per frame of a sprite file, into out/
rustyzoo check-sprites                            # decode every sprite file; a defective palette is a warning; exit 1 if one fails
rustyzoo --data "/path/to/Zoo Tycoon" which animals/lion.ai   # which file or archive supplies it, and the copies it hides
rustyzoo movie-info mslogo.avi --dump 100 out/    # size, frames, frame rate and audio of an intro movie (a game member or a file), decode every frame, write every 100th as a PNG into out/
rustyzoo map-info maps/default.zoo                # version, size, terrain and entities of a map or saved game
rustyzoo check-maps                               # read every .zoo file; exit 1 if one is corrupted
rustyzoo check-exhibits '*.zoo'                   # the exhibits each map's fences make, against the habitat count and first tiles it stores, and the tanks (exhibits closed by tank walls only) against its stored tanks; exit 1 if one differs
rustyzoo find-path maps/med_kids.zoo 23,59 37,59 --unit keeper   # the path the finder gives a keeper, guest or animal between two tiles (a partial path accepted), with its cost, one x,y line per tile; --task leave (or avoid, chase, ...) asks as a unit with that task
rustyzoo render-ani objects/aviary/idle/idle.ani out/   # frame 0 of an animation set, one PNG per screen direction, into out/
rustyzoo render-ani animals/lion/f out/ --anim walk     # the same for animals/lion/f/walk/walk.ani
rustyzoo check-anis                               # load every animation set and its sprite files; a defective palette is a warning; exit 1 if one fails
rustyzoo check-layouts [--expansions N]         # load ui/gamescrn.lyt and every layout it names; print the elements per type, duplicate ids and pictures; N is the expansion mask (bit 1 and bit 2, the `id` of an xpac*.cfg), default the install's; exit 1 if the load fails
rustyzoo dump-layout --size 800x600              # resolve the interface tree for a window (default 1024x768) and print id, type, layer, state and the screen rectangle of every element in drawing order
rustyzoo render-ui out.png --show 26 --hover 7111    # paint the interface headless (black frame, the root, the layouts of --show, a hovered and a pressed element) into a PNG; --size WxH (default 1024x768)
rustyzoo check-ground                              # render every cached ground picture again and compare; exit 1 if a covered pixel differs
rustyzoo render-ground ztats/000004 out/g.png     # render one ground picture (key as in the cache names)
rustyzoo render-map maps/default.zoo out.png --rotation 1   # draw a whole map into a PNG at normal zoom, and print what was drawn
rustyzoo render-map maps/default.zoo out.png --view 0 0 800 600 --no-units   # only the 800 x 600 window of the view whose top left pixel is the view-space point (0, 0), without animals, guests and staff
rustyzoo render-map maps/default.zoo out.png --grid   # draw the grid lines of every tile (without --grid only those at cliff tops appear)
rustyzoo sim maps/default.zoo --ticks 1000 --hash   # run a map for 1000 steps of 67 ms without an interface and print the hash of the whole state (tiles, entities, units, exhibits, money, zoo status, calendar, clocks, generator), the same on every system; `--dt MS`, `--seed S` (default 1) and `--script FILE` (`<step> remove ID`, `bulldoze ID` for the bulldozer's deletion with its refund, which pushes the users out of a building, `tile TX TY ELEVATION SHAPE TERRAIN`, `fill ID`, `drain ID`, `cash N`, `leave ID` for a guest that decides to leave, `food X,Y TYPE [UNITS]` puts down a pile of food of a type such as `herbchow`, full unless UNITS is given, `heal ID` heals an animal as a keeper's heal does, without the keeper and its booking, `guide X,Y` puts a tour guide on a tile without the hiring cost; `keeper X,Y` a marine specialist and `worker X,Y` a maintenance worker, hired without the cost; `animal TYPE X,Y [male|female]`, an animal of the sex given (the species' subtype of that sex, or its first, which then has that sex); `mood ID N`, an animal's happiness; `filter X,Y DIRECTION`, a tank filter facing a direction 0 to 7) change the run, `--reset-fences` makes every fence piece healthy first (as a start whose map file has `resetfences` above 0 does; the pieces of a map older than version 55 are made healthy anyway; otherwise they stay as the map stores them), `--log` prints the log lines of each step (among them `fence ID life L strength S [decayed|broken]` for a fence piece that wears) instead; at each month end the wage of every staff member (`sim wages ID AMOUNT`, keeper 11, guide 12, worker 13) and the upkeep of the guest buildings (`sim upkeep AMOUNT`, category 28) are taken from the cash whatever it is
```

`movie-info` reads the intro movies (AVI files with Indeo 5 video, 640x480 or 800x600, and PCM audio; the `.wmv` copies are not used). The window does not play them yet.

Files are found the way the game finds them: in the directories listed in `[resource] path` of `zoo.ini` (the install folder itself if there is no such key), the earlier directory winning, ignoring letter case, with `/` or `\` as separator. Inside a directory the loose files come first, then the archives (`.ztd` and `.zip`); among the archives of one directory the one whose lower-cased name sorts last wins, so `magnet02.ztd` beats `magnet01.ztd`, which beats `magnet.ztd`.

The names, descriptions and labels the game shows are not in the `.ztd` archives but in the resource DLLs of the install folder (`lang0.dll` and its siblings). `dump-strings` prints the string table of one DLL, newline, tab, backslash and other control characters escaped (`\n`, `\t`, `\\`, `\u{0000}`), followed by the name and size of its `TEXT` entries; `--text` writes the bytes of one of them.

Text is drawn in Liberation Sans (Regular and Bold, SIL Open Font License 1.1, embedded unmodified; see `fonts/README.md`), which has the metrics of the Arial the original asks for: the pixel size is `round(points * 96 / 72)`, a line is ascent plus descent of Arial's vertical metrics tall, every character advances by a whole number of pixels and there is no kerning. `text-width` prints the width of a text that way; `--font` is the face string of a layout file (`Arial` or `Arial Bold`, a bold face for any name with ` Bold`) and `--size` its size string (the leading digits are the points, 8 without any, at most 200).

`draw-text` lays a text out and draws it as the original does, on a canvas `--width` pixels wide and as tall as the text, filled with `--back` (white) and written with `--fore` (black), and prints the size and a hash of the pixels. Words wrap at spaces, a carriage return or line feed ends a line, a word wider than the width is cut and ends with `...`, `--justify` aligns each line (`left`, `center`, `right`), `--shadow` draws a black copy one pixel (two at 14 points) left and down first, and everything is clipped to the canvas. The text colour is reduced to the 16-bit surface by dropping low bits and the background by the game's own rule, glyphs of 9 to 16 pixels per em are drawn without smoothing, the others smoothed towards the background colour. The same hash comes out on every system.

The game loads every `lang*.dll` of the install folder, ordered by file name from the greatest to the smallest (`lang300.dll` first, `lang0.dll` last), and a string number or a `TEXT` name comes from the first library that has it non-empty. `strings` prints that merged view; the `[lib]` and `[language]` entries of `zoo.ini` are not used.

## Settings and saved games

RustyZoo never writes into the game folder. What it changes goes in a folder of the user:

| System | Settings (`zoo.ini`) | Saved games (from M7) |
| --- | --- | --- |
| Linux | `$XDG_CONFIG_HOME/RustyZoo` (default `~/.config/RustyZoo`) | `Saved Games` in `$XDG_DATA_HOME/RustyZoo` (default `~/.local/share/RustyZoo`) |
| Windows | `%APPDATA%\RustyZoo` | `Saved Games` in the same folder |
| macOS | `~/Library/Application Support/RustyZoo` | `Saved Games` in the same folder |

The `zoo.ini` of that folder holds only the keys RustyZoo changed. It is read on top of the `zoo.ini` of the game, in the same dialect: a key set there replaces the key of the game, every other key stays. A file that cannot be read is skipped with a warning. The environment variable `RUSTYZOO_USER_DIR` replaces both folders by one (tests and CI use it, so they never touch the real one).

## The window

`rustyzoo run <map>` opens a window and plays the map in it (`rustyzoo run` alone starts up to the main menu: first the two logo movies (`MSLOGO.AVI`, then `BFLOGO.AVI`, when `[UI] playMovie` and `playSecondMovie` are not 0; a key or a mouse button stops the movie that plays; the files of the trials are fewer, a missing one is skipped), then the start-up picture of the expansion flags with a progress bar over it while the game data loads, the menu music, then the main menu, where Continue is enabled when `[user] lastfile` names a file, Zoo Items and the button that loads a saved game are disabled (until saved games come), the scenario button shows the list of the scenarios (`scenar*.cfg`, by ascending section name, with an icon for each: won, playable or locked, from `[scenario]` of the ini file) with the picture and story of the selected one, and the freeform button the list of the maps (`free*.cfg`) with the picture and description of the selected one and the starting cash (a spinner or a typed amount between `[UI] MSMinCash` and `MSMaxCash`, written back to `MSStartingCash` of the settings of the user folder) with its difficulty (Play opens the map of the scenario or freeform file as a saved game, hiding the menu and starting the music's fade; a file that does not load is a message and the menu stays), Credits shows the credits pages one after the other (every `[credits] delay` seconds, 8 by default, of the interface clock, from the files `ui/credits/credit*.cfg`) and Exit ends the run; the number of loading steps is written to `[UI] progresscalls` of the settings of the user folder, and a first-run tutorial is not started yet) with the loop of the original: it handles all waiting events, runs the three timers (draw, interface, simulation) on the real clock, and sleeps until the next one is due. Closing the window ends the run from the menu; in a game it asks whether to save first (saving comes later: Yes changes nothing, No ends the run or, for Escape and the options panel's Main Menu, goes back to the menu).

- The game is `screenwidth` x `screenheight` pixels in the ini file, cut to the usable area of the display; `--size WxH` overrides it and is not cut (the factor still gives way if the window does not fit). The window is enlarged by the display scale (see below).
- `[user] fullscreen` of the ini file (a number other than 0; the shipped files have 1) starts the run in full screen, with the zoom limit of a full screen applied to the map's stored zoom; a window that cannot switch stays a window, with a warning. Every switch that succeeds (Alt+Enter, a script, the window manager) writes `fullscreen=1` or `fullscreen=0` into the `zoo.ini` of the user folder (see above), which the next start reads over the game's file. `--headless` does not read the ini mode: a headless run is full screen only through its script.
- The window can be resized, and its maximise button goes to full screen (the window is restored first, so leaving full screen gives a normal window). The game keeps its size at every window size: the picture is scaled by the largest whole factor that fits and centred on black, as in full screen, and the mouse is mapped back. A resize does not change the game size, so the zoom limit of a full screen is applied by the switch to full screen, not by the resize.
- Alt+Enter (on the release of Enter) switches between the window and full screen. A full-screen window without the focus blocks the loop like a minimised one. The game keeps its size: in full screen the picture is scaled by the largest whole factor that fits the display and centred on black, and the cursor over the black counts as the nearest edge of the picture, so the edge scroll works at the edge of the display. Full screen has an edge band of 2 pixels instead of 7, and a game 800 pixels wide cannot zoom in there (and is zoomed out to the normal zoom when it switches). In a script, `fullscreen on` and `fullscreen off` ask the window to switch; the log has the line when the game has switched. A window system that does not report full screen (the dummy video driver on some systems) is followed by the switch it accepted.
- `--passes N` ends the run after N passes, `--timing MS` after MS milliseconds. `--log FILE` writes the lines a headless run prints, and `run --headless --replay FILE` plays them again with the same frame hashes (the log tells the seconds that seeded the random generator, `sim seed S`, also when they came from the wall clock, and a replay seeds with them). `run --headless` needs no window at all: it takes a scripted clock (`--passes` with `--clock`) or a replay.
- While the window is minimised or hidden, the loop blocks (no drawing, no simulation, almost no CPU) and resumes when it is shown again.
- While the window does not have the input focus (another application is in front, or it is minimised) the sound is silent: the output device is muted and the voices keep running, so the music is heard again where it has got to when the focus returns. This also holds while the loop is blocked (minimised, hidden, or full screen without the focus): the audio thread queues the music loop again when it runs low, so the music goes on silently and is not stopped or restarted by the sleep.
- While the game is paused or a dialog is open, every sound that is playing is muted by 50 dB and gets its volume back at the end; sounds that start meanwhile are not muted. A unit's call that is already playing and is called again takes the new volume and the new pan for what is left of it. With `[advanced] use8BitSound` in `zoo.ini` a number other than 0, read at start-up, every sound is looked for under `altsound/` first and falls back to its normal name.
- `--timing MS` prints, for each timer, the count, minimum, median, 95th percentile and maximum of the gaps between its firings in milliseconds, next to the period it should keep, and a histogram of the gaps. It is information: nothing fails on a value.
- `--shot FILE` reads back what the renderer presents and writes it as a PNG, in pixels of the output.

High-density displays: the window is enlarged by the display scale, rounded to a whole number `k` (at least 1), so it has the size of the original's window and the picture stays sharp on every system: an 800x600 game is 1600x1200 pixels at 200%, on Windows and X11 (where the window size is in pixels) as well as on macOS and Wayland (where it is in points, 800x600, with twice the pixels). SDL scales the game picture to the window with the nearest pixel, so every game pixel is `k` x `k` screen pixels. If the enlarged window does not fit in the usable area of the display, `k` is lowered (not below 1) and the game size is kept. The run prints the game size and `k`, the three sizes (window, window in pixels, renderer output; the last two must match) and the display scale. The factor is chosen when the window opens and is not changed when the display scale changes later.

CI runs the window on every system with the dummy video driver (`SDL_VIDEO_DRIVER=dummy`, the software renderer and `SDL_AUDIO_DRIVER=dummy`): no window server or sound card is needed (the dummy driver has no pointer: the edge scroll reads none, only `pointer` lines of a script), and it checks the game size, the factor, the three sizes, the frames painted and the replay of the log. A second step opens a real window on the video driver of the runner (X11 on a virtual display on Linux, Cocoa, Windows), reads the pixels back with `--shot`, and prints in the log the game size and factor, the three sizes, the display scale, the number of colours and the hash of the picture; it fails only if the window mode breaks or the picture is blank, and, at factor 1, checks that the hash equals the hash of the last frame painted in the log of the run. The picture is not published. A further step prints the `--timing` summary of a ten second run in the log.
